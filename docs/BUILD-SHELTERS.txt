PRIVATE BUILD ENTRY POINT

Run src/build_prototype.py with Python 3.11 or newer and a JDK 25 installation.
The default preset is Shelter 22 38. Shelter 22 28 is a separate explicit preset;
other source cells, the SPD variants, and arbitrary maps are not supported.

Examples (choose a fresh tag each time):
  python -B src/build_prototype.py --tag prototype-v005 --shelter 22-38
  python -B src/build_prototype.py --tag prototype-v006 --shelter 22-28

The builder reads separately obtained local game/Workshop files. It does not
download, install, enable or publish mods, start a game client/server, or edit saves.
Existing output directories are refused and left intact. Conversion outputs,
compiler files, logs and receipts remain under this checkout's private directory.
They include third-party assets and are not repository source deliverables.

LOCAL PATHS

Each command-line option overrides its corresponding environment variable:
  --runtime       PZ_SHELTERS_RUNTIME
  --workshop-root PZ_SHELTERS_WORKSHOP_ROOT
  --jdk-bin       PZ_SHELTERS_JDK_BIN
  --output-root   PZ_SHELTERS_OUTPUT_ROOT

Compatibility defaults are private/runtime, the default Windows Steam
workshop/content/108600 path, tools/jdk-25.0.4.1+1/bin, and private respectively.
--runtime may point to a local stock game directory with projectzomboid.jar and
media; it is read-only input. --output-root must resolve inside this checkout's
private directory. The JAR SHA-256 guard remains mandatory:
  e1a69eb743ede60b213a0fe7f8b83d4fcab773036d256cc4543a336f3b058a33

Only the five converter/validator Java sources named in build_prototype.py are
compiled into each new output's classes directory. Unrelated diagnostic helpers
are excluded. No previous compiled classes are required. Injected Java options
are removed from the compiler and converter process environment.

VALIDATION AND REFERENCE COMPARISON

The original map conversion, vanilla edge merge, square/tile comparisons,
independent binary metadata audit, overlay clipping and current-game binary
parser checks remain in the main build. Read each build's logs and receipt.
The builder also creates package-manifest.json beside the mods directory and
verifies it immediately. The portable manifest fingerprints payload files, mod
IDs, game/converter versions and declared required directories, including empty
map-discovery scaffolding. It contains no machine-specific absolute paths.
--converter-version sets the release label (default 0.1.0).
build-receipt.json records the package fingerprint. To recheck a copied package:
  python -B src/package_manifest.py verify path/to/mods --manifest path/to/package-manifest.json

Optional --reference-build private/prototype-v003 verifies the old build against
its recorded manifest, compares every output payload file and checks the old
build again. Any added, missing or changed payload fails the build comparison.
reference-comparison.json records the result. Timing, logs and receipts are not
package payload and are intentionally excluded from the byte comparison.

The first integrated metadata build, prototype-v004, reproduced all 183 payload
files of accepted prototype-v003 byte for byte. This preserved the user-accepted
visual result; the rebuild itself did not launch a graphical client or server.
Subsequent explicit-preset regression results are recorded in their private
reference-comparison.json files rather than inferred from the earlier success.

BOUNDARIES

These are private compatibility prototypes. Original legacy objects.lua is kept
only as a non-loadable audit reference; vanilla zoning/biomes remain the default.
Biome equivalence, multiplayer behavior and long-running gameplay need separate
validation. The user's Shelter 22 38 visual/traversal/resume observations do not
establish correctness of Shelter 22 28 or untested sprites.
